Yarn Twist Visualizer

A parameterized geometric model of yarn twist. TPI, yarn count (Ne), and twist direction drive the rendered fiber structure in real time. Twist angle and helix pitch are computed from the inputs. Two rendering modes — zigzag approximation and true helix — can be compared side by side, and either can be placed beside a photograph of real yarn at the same parameters.

Model & assumptions

This visualizer is a parametric model, not a physical simulator. It encodes three textile parameters and renders the resulting fiber structure. The goal is to make the relationship between twist parameters and visible yarn structure explorable, and to allow the model to be compared directly against photographed yarn.

What is modeled

  • Yarn count (Ne) is a linear density. Diameter scales approximately with the inverse square root of linear density, so the default radius is radius = k / √count. A toggle switches to the simpler linear form radius = k / count for visual comparison — the linear form is not physically motivated and is kept only as a reference.
  • TPI (twists per inch) sets the number of visible turns along the rendered yarn length, capped at 20 turns for legibility.
  • Twist direction (S or Z) flips the handedness of the rendering: in zigzag mode, the lateral offset of alternate segments; in helix mode, the handedness of the helix itself.

Two rendering modes

  • Zigzag approximation — the original renderer. Alternate segments are offset left and right, producing a zigzag. It reads as twist at a glance but does not follow the computed twist angle.
  • True helix — a genuine helical path whose amplitude and pitch are driven by the computed twist angle. This mode follows the model's own mathematics; it is the mode to compare against photographed yarn.

Twist angle

For a helix, tan θ = π · d · TPI, where d is yarn diameter. In model units we treat d = 2 · radius. The computed angle is shown in the derived quantities.

Known limitations

  • The value of k in the radius formula is a display constant, not a measured physical quantity.
  • Fiber count is fixed at 5. Real yarns have far more fibers; the relationship between fiber count and visible texture is not modeled.
  • The model renders a single yarn segment in isolation. It does not model fabric, crimp, or inter-yarn interaction.

How to compare against reality

  1. Photograph real yarn of known Ne and TPI against a neutral background, with a scale reference.
  2. Set the model to the same Ne and TPI, and switch to true helix mode.
  3. Upload the photograph using the reference panel.
  4. Note where the model's silhouette diverges — twist angle, fiber count, packing density.
